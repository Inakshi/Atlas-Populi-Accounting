# General Finance Drive

**Accountable owner:** Finance  
**Scope:** Current organisation of the General Finance Drive and the boundaries an authorised agent must follow when navigating or placing files.

## Purpose and scope

The [General Finance Drive](https://drive.google.com/drive/folders/0APRguDe8RDf9Uk9PVA) belongs to Atlas Populi and is the main storage location for its Finance records and supporting documents. It also contains selected Atlas Labs and Horcery material because the same people support Finance work for all three entities.

The shared location does not combine the entities. Before searching for, reading, interpreting, creating or updating a file, an agent must confirm the legal entity relevant to the task.

This document explains the current folder structure and where files belong. It does not define how the underlying Finance processes are performed. Those instructions belong in the applicable SOP or skill.

## Documentation and operational records

GitHub is the authoritative location for current Finance context, policies, SOPs, skills and agent responsibilities. The `0. Finance Processes and Policies` area in the Drive contains legacy material that is being replaced by GitHub and must not be used as current operating guidance.

The Drive remains the operational location for Finance records, working documents and supporting evidence. Current transactions, financial records and case-specific evidence remain in the Drive or the other designated operational system; they must not be copied into this repository.

Loose files at the root of the Drive are outside the documented navigation structure and should be ignored unless the owner gives a specific instruction about one of them.

## Agent boundaries

An agent must obtain task-specific permission before it searches, reads, creates or updates content in the Drive. The permitted action and target must be clear.

After receiving permission, an agent may:

- search for and read relevant files;
- update an existing file within the authorised scope; and
- create a new file in the correct existing folder.

An agent must not:

- delete a file or folder;
- use the Drive root or a miscellaneous folder as a default location;
- move, rename or otherwise reorganise content unless that action is specifically authorised; or
- create a folder without specific permission.

If the correct folder does not exist, including at the start of a new financial year, the agent must ask for permission to create it. It must not create the folder or place the file elsewhere until permission is given. After an authorised creation or update, the agent must read back the result and report the exact file and folder used.

## Financial-year folders

Atlas Populi's financial year runs from 1 April to 31 March. Where a Finance category is divided by financial year, an agent must identify the applicable financial year before selecting or creating a file.

For payment-related records, the payment transaction date determines the Atlas Populi financial year. Period rules for other processes belong in their applicable SOP or skill; the agent must not invent them.

When a financial-year folder exists, the agent must use it. If it does not exist, the agent must follow the permission rule above before creating the new folder. Financial-year labels and dates must not be carried from Atlas Populi to Atlas Labs or Horcery without confirmation.

Within Internal Reporting, an agent should use financial-year folders wherever they exist. Where the current structure instead uses a calendar year, business unit, project or reporting period, the agent must follow that existing structure.

## Current folder structure

### 0. Finance Processes and Policies

This contains legacy process, policy, template, draft and inactive material. Ignore it as a source of current instructions. Use the approved documentation in GitHub.

### 1. Corporate: Atlas Populi

This is the principal storage area for Atlas Populi Finance records.

| Folder | Current use and navigation |
|---|---|
| `1. Payment Vouchers` | Payment Voucher records and related documents. The main structure is by financial year. Use the payment transaction date to select the applicable Atlas Populi financial year. The area also contains payment analysis and batch-payment support. | `2. Petty Cash` | Petty-cash records and supporting documents, organised by financial year. Detailed petty-cash handling belongs in its own SOP or skill. |

| `7. Audit Requirements` | Audit-related documents, organised by financial year. An agent working on audit material must use the correct financial-year folder. |
| `8. Document Storage` | An existing general document-storage area. Use it only when the task or an authoritative source identifies it as the correct location; otherwise ask. |

### 1.1 Corporate: Atlas Labs

This contains Atlas Labs Finance material. Confirm that the task relates to Atlas Labs before using it.

| Folder | Current use and navigation |
|---|---|
| `1. Audit Requirements` | Atlas Labs audit material, using the financial-year folders that exist. |
| `2. Payments` | Atlas Labs payment records. Annual Payment Voucher files are stored directly in this folder rather than in separate annual subfolders. Select the file matching the required period and ignore test files unless testing is explicitly requested. |
| `3. Receivables` | Atlas Labs receivables material, including archived and consulting-related subfolders. Use the specific existing subfolder that matches the task. |
| `4. Payroll` | Atlas Labs payroll-related records. Access or update these only when the task specifically requires them. |

Use its existing reporting, affiliate and other subject folders, and ignore superseded material unless historical review is specifically requested. |

### 2. Internal Reporting

This contains internal reports, budgets, forecasts, financial models, costing analyses, business-unit reporting, project reporting, and weekly or monthly reporting.

Navigate first by reporting category, then use the financial year, calendar year, business unit, named project, month or other reporting period already present. Use financial-year folders wherever they exist. Do not create a competing structure.

The current categories include:

- Costing Models.
- Projects, including active and inactive projects, data analytics, resource rates, project profitability and templates.
- Weekly Reporting.
- Business Units.
- Budgets and forecasts.
- Financial Models, Costings & Analysis.
- Ad Hoc Reporting.
- Monthly Reports.
- Monthly Transactions.
- Named working areas for specific budgets or projects.

### 3. Documentation

This contains training material, knowledge-transfer meeting records, agendas, run sheets and miscellaneous historical reference material. It is not the source for current policies, SOPs or skills; those belong in GitHub.

### 4. Operational Letters

This contains operational correspondence, including tax, statutory and bank-related letters. The structure uses a mixture of year, subject and recipient folders. Use the existing category and year where one is available. If no suitable location is clear, ask rather than creating a new structure.

### 5. Projects

This contains records for specifically named projects. Some project folders are further divided by month.

Use the existing folder for the named project and its applicable period. If the task's project folder or period folder does not exist, ask for permission before creating it. Do not place project material at the Drive root or in an unrelated project.

### 6. Archives

This contains older material. Ignore it unless the task specifically requires historical information.

## Navigation check

Before creating or updating a Drive file, the agent must confirm:

1. The task provides permission for the intended Drive action.
2. The correct legal entity is identified.
3. The correct top-level category is selected.
4. The applicable financial year or other period is identified where the structure uses one.
5. The correct existing folder is available, or permission has been obtained to create the missing folder.
6. The file will not be placed at the Drive root, in Inventory, in Archives, or in a miscellaneous folder merely because the correct location is unclear.
7. The completed write is read back and its exact location is reported.

If any of these points is unresolved, the agent must stop and ask.
